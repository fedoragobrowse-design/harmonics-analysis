# Harmonics Analysis 2.0.0

Version 2.0.0 expands the app from a live harmonic viewer into a more complete,
still-local practice and song-checking companion. Audio and score analysis remain
on the device. The new tools deliberately report observed evidence rather than
assigning a gender, permanent voice type, or promised singing comfort.

## What is new

### Speech profile alongside singing range

A conversational sample can now produce a spoken-pitch profile, based on the
10th, 50th, and 90th percentiles of clear voiced frames. Sustained vowels still
produce the separate observed singing range. The two modes are intentionally
not combined: speech is not treated as a singing-range test.

### MIDI and MuseScore song checks

Open a `.mid`, `.midi`, `.mscz`, or `.mscx` file to see its written pitch span.
After recording a take, compare the score span with the take's observed 5th–95th
percentile range. This is a range check, not a comfort, technique, or voice-type
promise; accompaniment and multi-part scores may widen the displayed span.

### Practice metronome and real microphone mute

The built-in local four-beat metronome accepts 30–300 BPM. The microphone mute
control stops the actual capture stream or process, which is useful when you
want the app open without recording any ambient sound.

### Expanded local MCP server

The local stdio MCP server now supports `inspect_score_file`, `check_song_range`,
and `open_harmonics_app`, alongside PCM-frame analysis. It only accepts the
explicit local paths or data supplied by its client; it does not scan files,
watch directories, upload content, or start recording on its own.

## Install and upgrade

- **Windows:** download `Harmonics-Analysis-Windows.exe` and its SHA-256 sidecar
  from the [v2.0.0 release](https://github.com/fedoragobrowse-design/harmonics-analysis/releases/tag/v2.0.0).
- **Debian/Ubuntu:** use `install-harmonics-analysis.sh` from the same release
  alongside the `.deb`; it stages the package where APT's sandbox can read it.
- **In-app update:** the app verifies the SHA-256 checksum before applying a
  supported release update.

See [the architecture guide](ARCHITECTURE.md) for signal-pipeline and score-tool
details, and [the MCP guide](MCP.md) for local integration.
